# Monitoring, Auditing Controls and Executive Reporting

## Project Overview

This project explores how security governance, control monitoring, vulnerability management, and executive reporting work together to strengthen organisational cybersecurity. Using a simulated Docker-based environment, I examined governance failures, implemented security controls, verified their effectiveness, and developed metrics to support management and board-level decision-making.

## Objectives

* Set up a simulated security environment using Docker and Docker Compose.
* Analyse security governance failures associated with patch management, database configuration, network segmentation, and monitoring.
* Compare laboratory findings with lessons from the Equifax data breach.
* Implement security controls and assess their effectiveness through verification and post-control testing.
* Develop security governance metrics, visualisations, and executive reporting materials.

## Tools and Technologies

* **Docker & Docker Compose:** Containerised laboratory environment.
* **MySQL:** Simulated customer database.
* **Vulnerability Scanning:** Identification of security weaknesses.
* **HTML Dashboard:** Presentation of security governance metrics.
* **Security Governance Reporting:** Documentation of risks, controls, compliance, and recommendations.

## Key Activities

The laboratory demonstrated how existing security processes can fail when controls are not effectively implemented or monitored. I analysed seven governance failures and implemented measures covering patch management, database security, network segmentation, monitoring, and governance oversight.

Post-implementation verification showed security improvements but also confirmed that the critical Struts2 vulnerability remained exploitable, highlighting the need for further remediation and continuous testing.

I also developed an executive dashboard, board report, metrics framework, and user guide. The reporting framework covered monitoring coverage, patch compliance, policy compliance, security incidents, and vulnerability remediation time.

## Key Learnings

* Security policies must be enforced, tested, and supported by evidence.
* Critical vulnerabilities require accountable ownership, remediation deadlines, and independent verification.
* Measurable indicators improve visibility, accountability, and management oversight.
* Continuous monitoring and reporting support informed risk-based decisions.

## Conclusion

This project strengthened my practical understanding of security governance, control assurance, vulnerability management, and executive reporting within a simulated environment.
